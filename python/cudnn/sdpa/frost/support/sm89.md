# SM89 SDPA support

[Back to the support index](README.md)

Scope: Ada **cc 8.9 exactly**, FROST graph `sdpa` forward; other cc 8.x parts
are not served by this engine. Forward is documented here; there is no FROST
SDPA backward engine for cc 8.9. The one engine is opt-in.

The engine uses the SM80 graph adapter, so the operand restrictions of the
[SM80 page](sm80.md) apply: Q, K, V and O are all FP16 or all BF16, softmax
precision is unset or FLOAT, and optional Stats are FP32 with natural-log or
base-2 output. FP8, MXFP8 and the other features the SM80 page lists as
unsupported are unsupported here too. `D_QK` is the Q/K head width and `D_V`
the V/output head width.

## Forward

| Engine name / public ID | Head domain and native geometry | Layouts and feature limits | Discovery |
|---|---|---|---|
| `sdpa_fwd_prefill_sm89` / **20530** | `D_QK, D_V <= 64`, each a positive multiple of 8; native D64 | Dense only, `H_q == H_kv`, `S_q > 1`; unmasked, top-left causal and left windows within the limits below | Opt-in with `CUDNN_FRONTEND_ENABLE_FROST_ENGINES=1` |

`(64,64)` uses the native width. Other admitted pairs, such as `(32,32)`,
compile the D64 geometry and mask loads past the declared widths, at D64 cost. Pairs above 64, such as `(128,128)`, and pairs that are not
eight-aligned, such as `(33,33)`, have no SM89 engine. The kernel is the SM80
K-prefetch body at one fixed geometry: 128 query rows, 64 keys, four warps.

### Combination and storage limits

- **Masks:** noncausal, causal with the top-left anchor, and left windows
  with or without the causal bound. `sliding_window_length=W` excludes keys
  with `query_index - key_index >= W`; with a causal upper bound, this keeps
  the `W` keys ending at the query position. Without that upper bound, future
  keys remain visible. `S_q` and `S_kv` are independent, and
  `S_kv` need not be a key-tile multiple. A graph declaring the bottom-right
  anchor is declined, as are right-widened bands.
- **Unsupported:** GQA/MQA, decode-shaped graphs (`S_q == 1`), padding masks
  and `seq_len_q` / `seq_len_kv`, THD and ragged offsets, paged KV, split-KV,
  PackGQA, sinks and bias.
- **Dense storage:** Q/K/V/O bind their declared `dense_flex` strides: any
  B/H/S order, D contiguous, nonoverlapping, every stepped B/H/S stride a
  multiple of 8 elements, with 16-byte-aligned runtime base addresses. Dense
  Stats are FP32 `(B, H_q, S_q, 1)` in a dense-compatible layout.
- **Shared memory:** the plan is built only when the compiled geometry's static
  shared memory fits the device's per-block opt-in limit; otherwise it is
  declined at build time.

## Backward

No FROST SDPA backward engine serves cc 8.9. The registered SM80 backward
engine `sdpa_bwd_sm80` (public ID **20601**) is limited to cc 8.0; see the
[backward engines](../../bwd/engines.py). Forward Stats do not imply backward
support.

## Plan selection and execution

The engine is offered only with `CUDNN_FRONTEND_ENABLE_FROST_ENGINES=1`.
Without it, the backend's plans serve these graphs. With it, the engine is a
candidate for the graphs above; eligibility does not promise first placement.
An explicit public `(engine_id, knobs)` record cannot change the tile geometry.

The dense host is compiled for the `sm_80` target, so one compiled artifact can
be reused by plans on cc 8.0 and cc 8.9 devices in the same process. Use the
shared [graph execution contract](../../../../../docs/utilities/python_graph_and_execution_backends.md).

The native cases need a cc 8.9 device and skip elsewhere; the standard FROST CI
has no cc 8.9 lane. They detect regressions in the cases they run, FP16/BF16
D64 and D32 graphs with the masks above, and do not cover asymmetric head pairs
or every admitted configuration. The determinism goldens have no entry for this
engine, and this page makes no performance claim.
