# SM89 FROST SDPA support

## Forward

Served by the SM80 forward rows on cc 8.9 under their
[shared-memory budget](sm80.md#shared-memory-budget-on-cc-86-and-89).

## FP16/BF16 backward

| Engine / public ID | Fixed implementation |
|---|---|
| `sdpa_bwd_sm89` / **20635** | Shared SM80 two-subgroup mma.sync chain, with the Ada 99 KiB shared-memory configuration |
| `sdpa_bwd_sm89_f16_d64` / **20636** | Shared dedicated D64 body for plain dense MHA with whole 64-row Q and 128-row KV tiles, packed Stats and no optional mask/bias/sink/deterministic features |

Both rows are available without opt-in on cc 8.9 only and trail the backend.
Their declaration checks select exactly one body before compilation. The
standalone `SdpaBwdDslSm89` retains the same D64/two-subgroup selection.
Neither SM80 engine ID is reused, and cc 8.6 is not admitted.

The two-subgroup owner retains the shared SM80 row's FP16/BF16 head envelopes
through D256, independent QK/V widths, MHA/GQA/MQA, causal/bottom-right and
window masks, dense per-sequence lengths, packed THD with independent physical
origins, packed Stats, bias/dBias and sink/dSink. These features compose only
where the common declaration and native-binding checks accept them. Native
MMA flavors cover smaller widths without an operand copy; the 99 KiB profile
uses one Q/dO stage, direct FP32 dQ atomics, 64x64 tiles through the D128
envelope and 32x32 above it. Deterministic dQ uses the existing ordered
reduction. Deterministic dBias requires a per-batch bias; the exact
head-width restrictions for auxiliary gradients remain unchanged.

Sources: [capabilities and fixed-body selection](../../bwd/engines.py),
[Ada adapter](../../bwd/api_dsl_sm89.py),
[shared body-selection contract](../../bwd/kernels/sm80/half_contract.py),
[shared native binding](../../bwd/prepared_sm80.py), and
[admission, gradients and replay tests](../../../../../test/python/sdpa/frost/test_sdpa_bwd_sm89.py).
The caller supplies workspace; selected records fix an implementation and do
not switch bodies during build or execution. No new batch-invariance or
performance claim follows from these rows.

## Other precisions

No FP8/MXFP8 backward capability is added by these half-precision owners.
