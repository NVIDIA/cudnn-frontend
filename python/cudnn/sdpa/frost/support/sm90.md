# SM90 SDPA support

[Back to the support index](README.md)

Scope: Hopper **cc 9.0 exactly**, FROST graph `sdpa` forward and the opt-in
`sdpa_backward` engine. Forward coverage and the backward engine's domain are
documented here. Q, K, V and O must all be FP16 or all BF16. Softmax precision is unset or FLOAT. Forward Stats are
optional FP32 with natural-log or base-2 output; the backward engine requires
natural-log FP32 Stats (it rescales them to base 2 itself, so base-2 Stats would
be rescaled twice). FP8, MXFP8, mixed Q/K/V/O types, bias, Amax output and
epilogue gate fusion are unsupported.

`D_QK` is the Q/K head width and `D_V` the V/output head width. THD means
token-packed variable-length storage. GQA/MQA require `H_Q` divisible by
`H_KV`; ordinary GQA does not require the PackGQA optimization.

## Forward

All three engines participate in ordinary discovery. The table describes graph
eligibility; the restrictions below also apply.

| Engine name / public ID | Head domain and native geometry | Layouts and feature limits |
|---|---|---|
| `sdpa_fwd_sm90_d64_one_wg` / **20539** | Exact `(64,64)`, native D64 | Dense, nonpaged, uniform lengths; noncausal or top-left/bottom-right causal; decode allowed. No THD, per-batch lengths, sinks, windows, PackGQA or split-KV. |
| `sdpa_fwd_sm90_f16_three_wg` / **20540** | Native D128/D256/D512 and bounded envelopes below; paged `(64,64)` uses D128 | Dense, nonpaged THD, or dense-Q paged KV. Supports masks/bands, lengths, sinks and decode within the combination limits below. Dense paths can use split-KV and PackGQA except at exact `(64,64)`. |
| `sdpa_fwd_sm90_d128_multi_q` / **20541** | Exact `(128,128)`, dedicated native D128 | Dense, nonpaged, uniform lengths; noncausal or top-left/bottom-right causal. No decode (`S_q == 1`), THD, per-batch lengths, sinks, windows, PackGQA or split-KV. |

The two D128 implementations are distinct public choices. The dedicated D128
engine has a 128 x 128 sequence tile; the three-WG engine uses 64 x 64. Features
declined by the dedicated engine may be served by the three-WG engine.
Nonpaged exact D64 has only its narrower native domain; it does not fall back
to a wider graph engine when a feature is declined.

### Head envelopes

Each dimension is independently a multiple of 8. The three-WG engine uses the
smallest covering native geometry whose bounds both dimensions satisfy:

| Storage/contraction geometry | Graph head envelope |
|---|---|
| D128 | `64 <= D_QK,D_V <= 128`; exact nonpaged `(64,64)` belongs to engine 20539 |
| D256 | `128 <= D_QK,D_V <= 256`, when D128 does not cover both |
| D512 | `256 < D_QK,D_V <= 512` |

Exact `(128,128)`, `(256,256)` and `(512,512)` use native widths. Other admitted
pairs use padding at the selected geometry's cost: `(120,72)` uses D128 and
`(192,128)` uses D256. `(256,512)` is outside the graph envelopes. The
standalone adapter accepts a wider eight-aligned head domain; that does not
extend graph eligibility.

### Combination and storage limits

- **Masks and lengths:** unpadded bottom-right or left-window declarations with
  `S_q > S_kv` are declined. Bottom-right bands need a right bound. Dense padding
  uses INT32 per-batch lengths; cumulative lengths are THD-only and dense Q-only
  trimming is unsupported. Sequence tails need not be tile multiples.
- **THD:** engine 20540 only, nonpaged, unsplit, unpacked, with NATURAL scheduling.
  Q/KV lengths are INT32 sequence lengths or cumulative lengths. Data must be
  token-major, with D contiguous and covering, 16-byte-aligned token/head strides.
  Stats may be packed token-major or packed head-major,
  with a head stride covering the physical token span. Dense-padded THD Stats
  are unsupported. Bound per-port ragged offsets are read on device, including
  independent Q/K/V/O/Stats origins. The workspace must have a 128-byte-aligned
  base and be contiguous or view-flattenable for capture-safe execution.
- **Paged KV:** engine 20540 only, with dense Q and device KV lengths. K/V may
  independently use HND or NHD pools and INT32 page tables; pool capacities must
  match. Page sizes are multiples of 8 that divide 64, or multiples of 64.
  Exact paged D64 uses D128 storage but remains unpacked and unsplit in graphs.
- **Split-KV and PackGQA:** only engine 20540's D128/D256/D512 graph domains;
  no THD combination. Dense-Q paged paths share these bounds. With
  `G = H_Q / H_KV`, packing accepts `G == 1` or `gcd(G,64) > 1` and uses that
  greatest common divisor as its subgroup width. For example, G12 packs groups
  of four; G3 is declined. Unpacked GQA remains available for G3.
- **Dense storage:** Q/K/V/O bind their declared `dense_flex` strides, with D
  contiguous, covering nonoverlapping pitches and TMA-compatible 16-byte strides.
  There is no layout conversion. Outputs, Stats and workspace must not overlap
  other operands, and storage must outlive execution. Accessed padded V rows
  must be finite.
- **Scale and sinks:** host scales may be positive, zero or negative. The
  three-WG engine accepts per-head FP32 sinks; a keyless active row returns
  `O = 0, Stats = sink`, while a Q-length-trimmed row returns `O = 0, Stats = -inf`
  in natural-log units. Base-2 Stats apply the corresponding conversion.

## Backward

### FP16/BF16, exact D64 and D128 key-owner chain

`sdpa_bwd_sm90` / **20634** is an opt-in engine: it is offered only when
`CUDNN_FRONTEND_ENABLE_FROST_ENGINES=1` is set, and then ranks with the other
FROST rows. It fixes the three-launch chain of a delta and scratch reset, one
key-owner kernel with an ordered fp32 dQ relay, and a dQ cast. The deterministic
and the default request run the same chain and return identical bytes.

| Engine name / public ID | Head domain | Layouts and feature limits |
|---|---|---|
| `sdpa_bwd_sm90` / **20634** | Exact `(64,64)` and `(128,128)` | Dense compact BSHD `Q/K/V/O/dO/dQ/dK/dV` with strides `(S*H*D, D, H*D, 1)`; contiguous FP32 natural-log `Stats` of shape `(B, H_Q, S_q, 1)`; FP16 or BF16 throughout; MHA, or GQA/MQA with `H_Q` divisible by `H_KV`; unmasked, top-left causal or bottom-right causal (`S_q <= S_kv`); positive sequence lengths of any size; `B` and `H_Q` at most 65535; positive finite host scale. Declined: THD, padding masks, windows, bias/dBias, sinks/dSink, dropout, other head widths or dtypes, any other layout. |

The workspace holds the fp32 dQ accumulator and delta rows over the
128-row-rounded `S_q`, one turn counter per 64-row query tile and one ticket
per query head (`relay_workspace_layout`); query the plan for its size. The
engine takes no knobs. Inputs, outputs and workspace must stay on the declared
CUDA device; `dQ`, `dK` and `dV` must not overlap each other or any input, and
the workspace must not overlap any operand. Execution performs no allocation or
layout copy and supports CUDA Graph capture and replay. The cuDNN backend's backward coverage is
separate; see the [attention API](../../../../../docs/operations/Attention.md).

## Plan selection and execution

An explicit public `(engine_id, knobs)` record fixes one implementation. The
three forward engines have different legal knob domains and the backward engine
takes none; an unsupported configuration is declined. Engine **20517 is retired and reserved**; old records must replan.
Automatic candidate ordering and placement remain heuristic decisions, so
eligibility does not promise selection ahead of the cuDNN backend.

Use the shared [graph execution contract](../../../../../docs/utilities/python_graph_and_execution_backends.md).
SM90 binds runtime operands through the prepared pointer path for dense and THD
plans. Execute-time shape/stride overrides are unsupported, and these engines
do not advertise `SUPPORTS_SDPA_STATS_STRIDE_OVERRIDE`. CUDA Graph replay keeps
the captured storage bindings; changed values in that storage are consumed.
