# SM107 SDPA support

[Back to the support index](README.md)

Scope: Rubin **cc 10.7 exactly**, FP16/BF16, per-tensor FP8 and MXFP8 forward.
Backward is **Pending migration** in this reference.
Pending documentation does not imply that a feature is unsupported.
The runtime must satisfy the [shared DSL gate](../../../frost/buffers.py)
(`cutedsl_state`) and support the SM107 target (`_cutedsl_has_sm107`).

## Small and medium half forward

The following fixed owners serve the physical QK / V flavors listed below and
their existing eight-aligned logical head-width envelopes.
They participate in ordinary enumeration; central heuristics retain the existing
candidate order, packing, split budgets and geometry choices. A legal owner need
not be the first candidate. FP16 and BF16 share these implementations; per-tensor
FP8 and MXFP8 attention use separate bodies.

| Main implementation / public ID | Physical QK / V flavors | Implementation boundary |
|---|---|---|
| `sdpa_fwd_sm107_d128_multi_q` / **20559** | 32 / 32, 64 / 64, 128 / 128; paged 192 / 128 | Ordinary multi-query work item, one or two CTAs |
| `sdpa_fwd_sm107_small_batch_pair` / **20560** | 32 / 32, 64 / 64 | Batch-pair work item with batch-broadcast bias; one CTA |
| `sdpa_fwd_sm107_d192_multi_q` / **20556** | 192 / 128 | Native nonpaged D192 body; two CTAs |
| `sdpa_fwd_sm107_d256_lookahead` / **20557** | 256 / 256; restricted 128 / 128 THD | Native lookahead body; D128 uses its one-query topology |
| `sdpa_fwd_sm107_d256_swap_ab` / **20558** | 256 / 256 | Native dense-query swap-AB body; 16, 32 or 64 query rows |
| `sdpa_fwd_sm107_shared_single_q` / **20569** | 32 / 32, 64 / 64, 128 / 128, 192 / 128 | SM107 contract for the shared SM100 single-Q body; one CTA |
| `sdpa_fwd_sm107_shared_d256_lookahead` / **20570** | 256 / 256 | SM107 contract for the shared SM100 lookahead body; two CTAs |

The two shared owners reuse SM100 kernel/config code. Their SM107 contracts
retain architecture-specific admission and lowering; they do not copy those
main kernels. Exact and envelope records on `sdpa_fwd_prefill_sm107` require
replanning to their explicit owners. Positive logical widths must be divisible
by eight and fit the listed covering flavor; for example, D176/V112 uses the
D192/V128 flavor. Those envelopes incur the covering geometry's MMA cost.
The [width contract](../../fwd/kernels/sm107/half_flavor_contract.py) classifies
widths; the shared capability walk still checks feature combinations and may
promote a small head to a larger flavor. Even an exact D32
logical head may use a D64/D128 envelope for a feature outside the native D32
geometry; the logical head size alone does not name the main implementation.

### Feature combinations

- Common graph checks retain the admitted causal, bottom-right, sliding-window,
  sink, Stats and declared-stride contracts. Every port must satisfy its own
  native binding requirements. Paging, THD, packing and split-KV are supported
  only in their existing admitted combinations, not as an unrestricted product.
  Envelope ownership does not widen THD or mixed-FP8-KV admission: those paths
  retain their existing exact-width checks, including the D128 one-query
  topology and nonpaged D256 THD split.
- Ordinary and batch-pair small heads retain their own resident/streamed bias
  resource limits. Batch-pair requires at least two batch entries and a bias
  broadcast over batch; it is dense, nonpaged, unpacked and unsplit. Its chunk
  size and two/three-query-group geometry are internal variants, not public
  engine knobs. Replaying it cannot switch to the ordinary work item.
  Its capability row does not advertise split-KV; split records are rejected.
- The native D128 one-query lookahead variant is same-dtype THD, one CTA,
  unpacked and unsplit, without bias, per-key mask, mixed KV or epilogue gate.
  D256 lookahead keeps the native fused gate and mixed-KV restrictions.
- Native D256 swap-AB has dense queries. A fused gate is applied only by its
  split combine; prefolded attention scale is declined. Its 64-row variant has
  the existing packing/mask constraints, especially with paged KV.
- Only native D256 lookahead and native D256 swap-AB declare fused gate
  support among these half owners. The shared bodies and other dimensions do
  not inherit that declaration; their graph records decline the gated tail.
- Shared single-Q has no additive bias, per-key mask or score side outputs.
  D192 requires nonpaged, unpacked THD with positive query capacity, packed
  Stats if declared, and no sink or epilogue gate. An explicit unsplit record
  needs no split-workspace total-Q bound. Small-head THD uses this owner for
  admitted split records; unsplit THD stays with a native owner. Dense paged
  small heads use the native body. Mixed FP8 KV is admitted here only at D128
  and remains subject to the shared adapter's layout/feature checks. Dense
  nonpaged D128 retains its pre-folded attention-scale rejection.
- Shared D256 lookahead serves same-dtype paged KV or compact nonpaged THD split.
  Nonpaged D256 split does not forward independent per-port physical origins;
  the strict expected-failure origin test retains this existing limitation.
  Native D256 lookahead serves the corresponding nonpaged THD unsplit record,
  including its supported independent origins.
  Changing `SPLIT_KV` can therefore require choosing a different engine before
  compilation; replay of a fixed engine never performs that choice internally.

Registration does not add a general batch-invariance or Stats-stride-override
claim. Consumers query the final plan's behavior notes and use the documented
fallback when a note is absent.

## Wide-head half forward

| Main implementation | Exact native QK / V dimensions | Physical CTA tile / cluster | Discovery |
|---|---|---|---|
| `sdpa_fwd_sm107_d512_role_split` | 512 / 512 | 128 query rows; four CTAs in two MMA pairs | Ordinary engine enumeration; heuristics retain their existing default choice |
| `sdpa_fwd_sm107_d512_2x2` | 512 / 512 and 576 / 512 | 64 query rows; four CTAs at uniform D512, two at D576 or mixed FP8 KV | Ordinary engine enumeration and existing candidate ranking |

FP16 or BF16 Q and O have the same dtype. Both owners serve same-dtype K/V.
The 2x2 owner additionally serves D512 with independent E4M3 or E5M2 K/V;
these mixed-storage plans use one MMA pair. Per-tensor FP8 and MXFP8 attention
operations belong to separate implementations.

The owners also accept their existing eight-aligned D512/V512 envelopes,
such as D384/V320. The D576/V512 flavor remains exact-only; it does not
cover heads between D512 and D576. Envelopes cost the covering geometry and
are not native dimensions. Exact and envelope records on
`sdpa_fwd_prefill_sm107` decline and require replanning.
Engine identity and public knobs fix the main implementation before compilation;
replaying an explicit record does not consult the standalone A/B switch.
`TILE_CGA_M` is the physical cluster; each implementation's MMA group has two CTAs.

### Feature combinations

- Both bodies support the admitted causal, bottom-right and sliding-window
  masks, sink, optional Stats, Stats log base, and pre-folded attention scale.
  They serve declared aligned dense strides through the common binding contract.
  Bias, per-key mask, score side outputs and fused epilogue gate are outside
  these wide-head owners' domain.
- The role-split owner is nonpaged, unpacked and unsplit. It serves dense
  or D512 THD declarations with same-dtype Q/K/V/O.
- The 2x2 owner serves native dense-query paging, PackGQA including partial
  head groups, and FP32 split-KV partials through the common combine kernel.
  The graph's page-table, pool-stride and workspace requirements still apply.
- THD is D512 only, with same-dtype operands, unpacked, unsplit and nonpaged.
  Independent Q/K/V/O origins and packed Stats use the existing native setup
  and binding chain. D576 THD and mixed-FP8-KV THD remain declined.
- Mixed FP8 KV is exact D512 with dense Q, with or without paging, packing
  and split-KV. Output remains Q's half dtype.

Capability columns do not imply an unrestricted Cartesian product. Query the
selected plan's behavior notes for its execution contract; registration alone
does not establish batch invariance. The
[determinism reference](../../../../../docs/operations/determinism.md) defines
the difference between repeatability and batch invariance.

## Forward

### Per-tensor FP8

Q/K/V use the same E4M3 or E5M2 format. O may be FP16, BF16, E4M3 or E5M2.
Scales and descales are FP32 scalar tensors. D128 multi-Q additionally supports
block-scaled O as described below; the other native geometries require scalar O.
Softmax precision is unset, FLOAT or HALF;
this is an operation attribute, not a performance knob. Optional Stats are
FP32, with natural-log or base-2 output. Optional Amax is a whole-output
reduction, not a per-sequence result.

Native multi-Q, single-Q and role-split rows participate in ordinary discovery.
The swap-AB record is available through explicit plan construction; the current
heuristics do not propose it automatically. Feature combinations remain subject
to the restrictions below.

| Engine name / public ID | Head domain and native geometry | Layouts and features |
|---|---|---|
| `sdpa_fwd_sm107_d128_fp8_multi_q` / **20563** | Native `(64,64)` and `(128,128)` plus their 16-aligned envelopes, native multi-Q | Dense masks/bands, lengths, sinks, decode, optional Stats/Amax, split-KV and whole-group PackGQA. Exact D128 additionally supports nonpaged THD; the D128 flavor supports block-scaled O. No paged KV. |
| `sdpa_fwd_sm107_d128_fp8_swap_ab` / **20564** | Native `(128,128)` and its 16-aligned envelope, shared swap-AB body | Dense nonpaged queries, FP32 softmax, scalar O; masks, lengths, sinks, Stats/Amax and fixed splits. All live query rows must fit eight columns: `S_q <= 8` unpacked, or `S_q * (H_Q/H_KV) <= 8` packed. NATURAL scheduling only. No THD. |
| `sdpa_fwd_sm107_d192_fp8_multi_q` / **20561** | Native `(192,128)` and its 16-aligned envelope, native multi-Q | Dense or exact-width nonpaged THD; masks/bands, lengths, sinks, optional Stats/Amax. Dense paths admit split-KV and whole-group PackGQA. No paged KV. |
| `sdpa_fwd_sm107_d256_fp8_single_q` / **20562** | Native `(256,256)` and its 16-aligned envelope, native single-Q | Dense or exact-width nonpaged THD with the same feature families. Exact D256 dense unsplit/unpacked graphs may fuse a BF16 sigmoid gate. No paged KV. |
| `sdpa_fwd_sm107_d512_fp8_role_split` / **20549** | Native `(512,512)` plus 16-aligned widths with both axes in `(256,512]`, native role-split | Dense, exact-width nonpaged THD, or dense-Q paged KV; masks/bands, lengths, sinks, decode, optional Stats/Amax. Dense paths admit split-KV and whole-group PackGQA. |

Envelope dispatch selects the smallest covering flavor: D64, D128,
D192/V128, D256, then D512. Each width is a multiple of 16. The first four
flavors cover widths up to their named dimensions; the D512 envelope
requires **both** widths in `(256,512]`. Exact shapes and envelopes use the
same fixed implementation owners above. D128 envelopes may explicitly select
shared swap-AB when its query-row bound holds. Padded heads retain the larger
flavor's storage and computation cost. Partial-head THD remains unsupported.

The legacy **20514** record (`sdpa_fwd_prefill_sm107_fp8`) declines these SM107
shapes as owned by the fixed implementations; saved legacy records require
replanning. The architecture range served by that row outside cc10.7 is
unchanged. The [width contract](../../fwd/kernels/sm107/fp8_flavor_contract.py)
and the registered capabilities enforce these boundaries.

### Combination and storage limits

- **Masks and lengths:** noncausal, top-left/bottom-right causal and diagonal
  bands are supported. Bottom-right bands require a right bound; unpadded
  bottom-right/left-window declarations with `S_q > S_kv` are declined. Dense
  padding uses INT32 per-batch lengths; cumulative lengths are THD-only.
  Scalar KV tails and empty actual lengths retain the graph's masking rules.
  Dense mask-free graphs that need a scalar KV-tail mask support split-KV
  at D128, D256 and D512; D64 and D192/V128 decline that combination.
- **THD:** exact D128 with CGA2, D192/V128, D256 or D512 only, nonpaged, unsplit and unpacked. Q/KV lengths are
  INT32 sequence lengths or cumulative lengths. Bound Q/K/V/O/Stats origins
  are independent device inputs. Packed Stats may be token-major or
  head-major; the head stride must cover the physical token span. An explicitly
  padded Stats declaration uses its declared dense strides instead.
- **Paged KV:** D512 only; dense Q with device KV lengths; no THD paging. K/V use
  independent INT32 page tables and independently declared HND/NHD pool strides;
  pool capacities must match. Page sizes are multiples of 8 that divide 128,
  or multiples of 128. Masks, sinks, packing and legal splits can compose.
- **PackGQA and split-KV:** dense and dense-Q paged paths only. With
  `G = H_Q / H_KV`, packing requires the whole group to divide 128. A group
  outside that packing domain may still use unpacked GQA. Split count is
  fixed by the selected record; it is not a bitwise-equivalence promise
  between different records. Native multi-Q, single-Q and role-split support
  NATURAL and LPT scheduling; D64/D128 and D192 also support LPT_L2.
  D256/D512 decline LPT_L2. Swap-AB uses its own record and NATURAL scheduling.
- **Block-scaled O:** native D128 multi-Q supports FP4 E2M1 with E4M3
  scale factors per 16 output elements, or E4M3 with E8M0 scale factors per
  32 elements. The caller supplies the matching `sf_o` declaration and
  storage. This requires fixed dense, untrimmed Q, unsplit and unpacked
  plans, with no paging, THD, shape overrides or sigmoid gate. FP4 requires
  block scaling; scalar FP4 O is not supported.
- **Storage:** D is contiguous; declared token/head pitches must cover the
  logical dimensions and satisfy TMA's 16-byte alignment. Bindings must expose
  the full declared storage span. There is no implicit layout conversion.
  Workspace must have a 128-byte-aligned base and be contiguous or
  view-flattenable for capture-safe execution.
- **Sigmoid gate:** exact D256 only, BF16 G, dense, unsplit and unpacked.
  O is multiplied by `sigmoid(G)`; Stats and Amax belong to the preceding
  attention node. D64/D128, D192 and D512 decline this fusion.
- **Other exclusions:** mixed Q/K/V formats, bias and prefolded attention
  scaling are unsupported in these graph domains.

### MXFP8

Q, K and V share one FP8 type, E4M3 or E5M2, with E8M0 scale factors per
32-element block. O is FP16, BF16, E4M3, E5M2 or FP4 E2M1. A block-scaled O
(FP4 E2M1 with E4M3 scales per 16, or E4M3 with UE8M0 scales per 32) is served
by the D128 engine only, on dense unsplit graphs without a gate. Softmax
precision is unset, FLOAT or HALF; this is an operation attribute, not a
performance knob. Every engine accepts the prefolded attention scale except
over paged KV. Optional Stats are FP32, with natural-log or base-2 output.
Optional Amax is a whole-output reduction.

Each engine serves one exact head shape; there is no envelope. All four are in
ordinary discovery.

| Engine name / public ID | Head domain and native geometry | Layouts and features |
|---|---|---|
| `sdpa_fwd_sm107_d128_mxfp8_multi_q` / **20565** | Exact `(128,128)`; two Q tiles, one or two CTAs | Dense or dense-Q paged KV. Bounded dense unsplit graphs also accept a one-CTA record. NATURAL, LPT and LPT_L2 scheduling. The only MXFP8 engine with split-KV and block-scaled O. |
| `sdpa_fwd_sm107_d192_mxfp8_multi_q` / **20566** | Exact `(192,128)`; two-CTA pair | Dense only. NATURAL, LPT and LPT_L2. A one-CTA record is accepted only for dense unsplit MHA causal graphs. |
| `sdpa_fwd_sm107_d256_mxfp8_single_q` / **20567** | Exact `(256,256)`; one or two CTAs (`TILE_CGA_M` 1 or 2) | Dense, nonpaged THD (one CTA) or dense-Q paged KV. NATURAL only. Fused `O * sigmoid(G)` epilogue gate with a BF16 G on dense graphs. |
| `sdpa_fwd_sm107_d512_mxfp8_role_split` / **20568** | Exact `(512,512)`; two-CTA role split | Dense only. NATURAL only. |

### MXFP8 combination and storage limits

- **Masks and lengths:** noncausal, top-left/bottom-right causal, sliding
  windows, widened right bands, padding masks and sinks compose on every
  engine. Dense padding uses INT32 per-batch lengths; cumulative lengths are
  THD-only.
- **THD:** D256 only, nonpaged, unsplit and at one CTA, with packed
  per-sequence-tile-padded scale factors. Stats may be token-major,
  head-major or per-batch padded.
- **Paged KV:** D128 and D256 only, with dense queries and a padding mask. The
  F8_128x4 descale pools page with K and V, so page sizes are multiples of 128.
  THD queries over pools, block-scaled O over pools and the prefolded scale over
  pools are declined.
- **Split-KV:** D128 only, on dense graphs with FP16/BF16 O and no sink. Split
  count is fixed by the selected record; it is not a bitwise-equivalence promise
  between different records.
- **Epilogue gate:** D256 only, dense and unsplit, no PackGQA, with a BF16 G.
- **Other exclusions:** PackGQA, swap-AB, bias, mixed Q/K/V formats and other
  head shapes are unsupported in this domain.

## Plan selection and execution

D64/D128 native shapes and their envelopes use **20563** for native multi-Q, with physical
CGA1 or CGA2; default geometry is CGA1 at D64 and CGA2 at D128. D64 permits
`TILE_N=64` or 128; D128 uses 128. Explicit **20564** fixes the shared swap-AB
body, `TILE_M=16`, `TILE_N=128` and CGA1. Its graph domain is specific to SM107
although its device body is shared with SM100.

D192/V128, D256 and D512 native shapes and their envelopes use **20561**, **20562** and
**20549** respectively. D192 uses `TILE_CGA_M=2`, with CGA1 also admitted
for dense, unsplit causal MHA with FP8 O and a bounded KV working set.
D256 uses CGA1. These values describe both the physical cluster and MMA group
for the two mid-width bodies. For D512, `TILE_CGA_M=4` describes
its physical four-CTA cluster; each MMA group has two CTAs. The mid-width and D512 sequence tile
is 128 x 128. An explicit record fixes this body during rebuild, binding and
CUDA Graph replay. Old records naming **20514** for any of these exact native shapes must be replanned;
that ID remains valid for its other eligible domains. Candidate ordering and
placement remain centralized. Eligibility does not imply first choice or a
performance guarantee.

An exact MXFP8 public record names its body: **20565** for D128, **20566** for
D192/V128, **20567** for D256 and **20568** for D512. Omitted performance knobs
use the selected implementation's defaults. To choose settings for a graph,
use heuristics and persist the resulting engine/knob record for replay. Old records naming
the MXFP8 row **20516** must be replanned; that row now only generates
candidates, budget and placement for these engines.

All engines use the shared
[graph preparation and execution contract](../../../../../docs/utilities/python_graph_and_execution_backends.md).
