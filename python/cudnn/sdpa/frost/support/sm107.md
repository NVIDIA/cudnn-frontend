# SM107 SDPA support

[Back to the support index](README.md)

Scope: Rubin **cc 10.7 exactly**, FROST graph `sdpa_fp8` forward at
D64, D128, D192/V128, D256 and D512, and `sdpa_mxfp8` forward.
FP16/BF16 forward and backward are **Pending migration**.
The runtime must satisfy the [shared DSL gate](../../../frost/buffers.py)
(`cutedsl_state`) and support the SM107 target (`_cutedsl_has_sm107`).

`D_QK` is the Q/K head width and `D_V` the V/output head width. THD means
packed variable-length token storage. GQA/MQA require `H_Q` divisible by
`H_KV`; ordinary GQA does not require the PackGQA optimization.

## Forward

### Per-tensor FP8

Q/K/V use the same E4M3 or E5M2 format. O may be FP16, BF16, E4M3 or E5M2.
Scales and descales are FP32 scalar tensors. D128 multi-Q additionally supports
block-scaled O as described below; the other native geometries require scalar O.
Softmax precision is unset, FLOAT or HALF;
this is an operation attribute, not a performance knob. Optional Stats are
FP32, with natural-log or base-2 output. Optional Amax is a whole-output
reduction, not a per-sequence result.

Native multi-Q, single-Q and role-split rows participate in ordinary discovery.
The swap-AB record is available through explicit plan construction; the current
heuristics do not propose it automatically. Feature combinations remain subject
to the restrictions below.

| Engine name / public ID | Head domain and native geometry | Layouts and features |
|---|---|---|
| `sdpa_fwd_sm107_d128_fp8_multi_q` / **20563** | Exact `(64,64)` and `(128,128)`, native multi-Q | Dense masks/bands, lengths, sinks, decode, optional Stats/Amax, split-KV and whole-group PackGQA. D128 additionally supports nonpaged THD and block-scaled O. No paged KV. |
| `sdpa_fwd_sm107_d128_fp8_swap_ab` / **20564** | Exact `(128,128)`, shared swap-AB body | Dense nonpaged queries, FP32 softmax, scalar O; masks, lengths, sinks, Stats/Amax and fixed splits. All live query rows must fit eight columns: `S_q <= 8` unpacked, or `S_q * (H_Q/H_KV) <= 8` packed. NATURAL scheduling only. No THD. |
| `sdpa_fwd_sm107_d192_fp8_multi_q` / **20561** | Exact `(192,128)`, native multi-Q | Dense or nonpaged THD; masks/bands, lengths, sinks, optional Stats/Amax. Dense paths admit split-KV and whole-group PackGQA. No paged KV. |
| `sdpa_fwd_sm107_d256_fp8_single_q` / **20562** | Exact `(256,256)`, native single-Q | Dense or nonpaged THD with the same feature families. Dense unsplit/unpacked graphs may fuse a BF16 sigmoid gate. No paged KV. |
| `sdpa_fwd_sm107_d512_fp8_role_split` / **20549** | Exact `(512,512)`, native D512 role-split | Dense, nonpaged THD, or dense-Q paged KV; masks/bands, lengths, sinks, decode, optional Stats/Amax. Dense paths admit split-KV and whole-group PackGQA. |
| `sdpa_fwd_prefill_sm107_fp8` / **20514** | Remaining 16-aligned head envelopes, excluding separately owned exact shapes | Dense; the D512 envelope additionally supports dense-Q paging. No partial-head THD. See the envelope bounds below. |

Envelope dispatch selects the smallest covering flavor: D64, D128,
D192/V128, D256, then D512. Each width is a multiple of 16. The first four
flavors cover widths up to their named dimensions; the D512 envelope
requires **both** widths in `(256,512]`. Exact native shapes use their
explicit owners above. D128 envelopes may use shared swap-AB when its
query-row bound holds. Padded heads retain the larger flavor's storage and
computation cost.

### Combination and storage limits

- **Masks and lengths:** noncausal, top-left/bottom-right causal and diagonal
  bands are supported. Bottom-right bands require a right bound; unpadded
  bottom-right/left-window declarations with `S_q > S_kv` are declined. Dense
  padding uses INT32 per-batch lengths; cumulative lengths are THD-only.
  Scalar KV tails and empty actual lengths retain the graph's masking rules.
  Dense mask-free graphs that need a scalar KV-tail mask support split-KV
  at D128, D256 and D512; D64 and D192/V128 decline that combination.
- **THD:** exact D128 with CGA2, D192/V128, D256 or D512 only, nonpaged, unsplit and unpacked. Q/KV lengths are
  INT32 sequence lengths or cumulative lengths. Bound Q/K/V/O/Stats origins
  are independent device inputs. Packed Stats may be token-major or
  head-major; the head stride must cover the physical token span. An explicitly
  padded Stats declaration uses its declared dense strides instead.
- **Paged KV:** D512 only; dense Q with device KV lengths; no THD paging. K/V use
  independent INT32 page tables and independently declared HND/NHD pool strides;
  pool capacities must match. Page sizes are multiples of 8 that divide 128,
  or multiples of 128. Masks, sinks, packing and legal splits can compose.
- **PackGQA and split-KV:** dense and dense-Q paged paths only. With
  `G = H_Q / H_KV`, packing requires the whole group to divide 128. A group
  outside that packing domain may still use unpacked GQA. Split count is
  fixed by the selected record; it is not a bitwise-equivalence promise
  between different records. Native multi-Q, single-Q and role-split support
  NATURAL and LPT scheduling; D64/D128 and D192 also support LPT_L2.
  D256/D512 decline LPT_L2. Swap-AB uses its own record and NATURAL scheduling.
- **Block-scaled O:** native D128 multi-Q supports FP4 E2M1 with E4M3
  scale factors per 16 output elements, or E4M3 with E8M0 scale factors per
  32 elements. The caller supplies the matching `sf_o` declaration and
  storage. This requires fixed dense, untrimmed Q, unsplit and unpacked
  plans, with no paging, THD, shape overrides or sigmoid gate. FP4 requires
  block scaling; scalar FP4 O is not supported.
- **Storage:** D is contiguous; declared token/head pitches must cover the
  logical dimensions and satisfy TMA's 16-byte alignment. Bindings must expose
  the full declared storage span. There is no implicit layout conversion.
  Workspace must have a 128-byte-aligned base and be contiguous or
  view-flattenable for capture-safe execution.
- **Sigmoid gate:** exact D256 only, BF16 G, dense, unsplit and unpacked.
  O is multiplied by `sigmoid(G)`; Stats and Amax belong to the preceding
  attention node. D64/D128, D192 and D512 decline this fusion.
- **Other exclusions:** mixed Q/K/V formats, bias and prefolded attention
  scaling are unsupported in these graph domains.

### MXFP8

Q, K and V share one FP8 type, E4M3 or E5M2, with E8M0 scale factors per
32-element block. O is FP16, BF16, E4M3, E5M2 or FP4 E2M1. A block-scaled O
(FP4 E2M1 with E4M3 scales per 16, or E4M3 with UE8M0 scales per 32) is served
by the D128 engine only, on dense unsplit graphs without a gate. Softmax
precision is unset, FLOAT or HALF; this is an operation attribute, not a
performance knob. Every engine accepts the prefolded attention scale except
over paged KV. Optional Stats are FP32, with natural-log or base-2 output.
Optional Amax is a whole-output reduction.

Each engine serves one exact head shape; there is no envelope. All four are in
ordinary discovery.

| Engine name / public ID | Head domain and native geometry | Layouts and features |
|---|---|---|
| `sdpa_fwd_sm107_d128_mxfp8_multi_q` / **20565** | Exact `(128,128)`; two Q tiles, one or two CTAs | Dense or dense-Q paged KV. Bounded dense unsplit graphs also accept a one-CTA record. NATURAL, LPT and LPT_L2 scheduling. The only MXFP8 engine with split-KV and block-scaled O. |
| `sdpa_fwd_sm107_d192_mxfp8_multi_q` / **20566** | Exact `(192,128)`; two-CTA pair | Dense only. NATURAL, LPT and LPT_L2. A one-CTA record is accepted only for dense unsplit MHA causal graphs. |
| `sdpa_fwd_sm107_d256_mxfp8_single_q` / **20567** | Exact `(256,256)`; one or two CTAs (`TILE_CGA_M` 1 or 2) | Dense, nonpaged THD (one CTA) or dense-Q paged KV. NATURAL only. Fused `O * sigmoid(G)` epilogue gate with a BF16 G on dense graphs. |
| `sdpa_fwd_sm107_d512_mxfp8_role_split` / **20568** | Exact `(512,512)`; two-CTA role split | Dense only. NATURAL only. |

### MXFP8 combination and storage limits

- **Masks and lengths:** noncausal, top-left/bottom-right causal, sliding
  windows, widened right bands, padding masks and sinks compose on every
  engine. Dense padding uses INT32 per-batch lengths; cumulative lengths are
  THD-only.
- **THD:** D256 only, nonpaged, unsplit and at one CTA, with packed
  per-sequence-tile-padded scale factors. Stats may be token-major,
  head-major or per-batch padded.
- **Paged KV:** D128 and D256 only, with dense queries and a padding mask. The
  F8_128x4 descale pools page with K and V, so page sizes are multiples of 128.
  THD queries over pools, block-scaled O over pools and the prefolded scale over
  pools are declined.
- **Split-KV:** D128 only, on dense graphs with FP16/BF16 O and no sink. Split
  count is fixed by the selected record; it is not a bitwise-equivalence promise
  between different records.
- **Epilogue gate:** D256 only, dense and unsplit, no PackGQA, with a BF16 G.
- **Other exclusions:** PackGQA, swap-AB, bias, mixed Q/K/V formats and other
  head shapes are unsupported in this domain.

## Plan selection and execution

Exact D64/D128 public records use **20563** for native multi-Q, with physical
CGA1 or CGA2; default geometry is CGA1 at D64 and CGA2 at D128. D64 permits
`TILE_N=64` or 128; D128 uses 128. Explicit **20564** fixes the shared swap-AB
body, `TILE_M=16`, `TILE_N=128` and CGA1. Its graph domain is specific to SM107
although its device body is shared with SM100.

Exact D192/V128, D256 and D512 public records use **20561**, **20562** and
**20549** respectively. D192 uses `TILE_CGA_M=2`, with CGA1 also admitted
for dense, unsplit causal MHA with FP8 O and a bounded KV working set.
D256 uses CGA1. These values describe both the physical cluster and MMA group
for the two mid-width bodies. For D512, `TILE_CGA_M=4` describes
its physical four-CTA cluster; each MMA group has two CTAs. The mid-width and D512 sequence tile
is 128 x 128. An explicit record fixes this body during rebuild, binding and
CUDA Graph replay. Old records naming **20514** for any of these exact native shapes must be replanned;
that ID remains valid for its other eligible domains. Candidate ordering and
placement remain centralized. Eligibility does not imply first choice or a
performance guarantee.

An exact MXFP8 public record names its body: **20565** for D128, **20566** for
D192/V128, **20567** for D256 and **20568** for D512. Omitted performance knobs
use the selected implementation's defaults. To choose settings for a graph,
use heuristics and persist the resulting engine/knob record for replay. Old records naming
the MXFP8 row **20516** must be replanned; that row now only generates
candidates, budget and placement for these engines.

All engines use the shared
[graph preparation and execution contract](../../../../../docs/utilities/python_graph_and_execution_backends.md).
